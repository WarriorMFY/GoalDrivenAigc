## 1. 冷启动：30 秒

```powershell
# ① 判定（唯一权威）：本周评论累计获赞 → 读 History\ledger.json 的 verdict
node Tool\bili\ledger.mjs report

# ② 偏差监控（不参与判定）：账号"内容获赞"，仅用于发现异常
node Tool\bili\sensor.mjs --print

# ③ 有新评论待回查时
node Tool\bili\ledger.mjs sync --pages 10

# ④ 审计判定数据是否可信（AGENTS.md §2 的机器检查）
node Tool\bili\audit.mjs
```

`ledger.json` 的 `verdict` 才是 LOOP 的判定；`state.json` 只是监控（它的 `verdict`/`gap_strict` 一律不作判据）。

`verdict = PASS` → 终止 LOOP；否则按 **`ledger.json` 的 `gap`** 规划（不是 `state.json` 的 `gap_strict`）。

## 4. 必须人工授权的工具

> 这一节与 `AGENTS.md §2`（"只能通过 `Tool\` 下的脚本改变世界"）是**叠加**关系：
> **能被脚本做到 ≠ 可以自动做**。下列工具在无人确认时**一律不执行**。

### 授权流程（三步，缺一不可）

1. **说明**——执行前用一句话讲清：目的、影响范围（本地/远端/账号）、能否回滚；
2. **取得明确同意**——等用户在**当前对话**里明确回答（"推吧" / "可以" / "执行"）。
   沉默、只问问题、模糊表述（"看着办"）**都不算授权**，此时不执行；
3. **留痕**——执行后在回复里报告：成功/失败、远端分支与 commit 号、影响范围。

### 授权粒度

默认**一事一授权**（一次执行 = 一次同意）。只有用户明确说"以后都行 / 本会话内都可"才放宽；即便放宽，每次执行仍必须报告结果。授权**不可跨会话继承**。

### 清单

| 工具 | 副作用 | 为什么必须授权 | 授权粒度 |
|---|---|---|---|
| `Tool\git\push.ps1` | 把本地提交推送到 GitHub `origin/main` | ① **远端可见且不可撤回**；② 使用真人的账号凭据；③ 是唯一会越过工作目录边界的动作 | 每次推送；重试不算重新授权，但更换远端/分支/强推必须重新授权 |

### 不在本清单里的（默认无需授权）

- 只读或本地派生：`sensor.mjs`、`ledger.mjs`（`report`/`list`/`sync`）、`audit.mjs`、`hunt.mjs`、`hotthread.mjs`、`proven.mjs` —— 它们只读 B 站公开接口、只写 `History\` 下的文件，删掉可重跑；
- **发评论**仍然只能人工，它压根不在脚本层，所以不进本清单。

### D1 · 2026-10-19 22:46 · `hotthread.mjs` v1 → v2：机会分从"根评论赞数"改成"楼内回复战绩"

**证据（同一晚的天然对照）**

| 楼 | 根评论赞 | 楼内回复赞数 | 说明 |
|---|---|---|---|
| `BV1wenJ65EFG` root=317558392545 | 264 | 16 / 11 / 7 | 楼里回复能拿两位数 |
| `BV1VMJi6GErN` root=317400656849 | 555 | 几乎无人回复 | 根评赞最高，但回复全在 1 赞 |

v1 的公式 `root_like / (rcount + 1)` 把"楼内回复多"当坏事——**方向反了**。真正的因果是：
**楼内回复真的拿到赞，才证明这个楼会把曝光分给回复**；根评论赞数只代表"这个楼有多显眼"。

**决策**：v2 用四个信号，全部来自接口、无一处靠猜

```
traffic   = view / age_hours                                      // 仍在被观看的速度
freshness = clamp(traffic / 5000, 0.2, 1.5)
proof     = reply_median*2.5 + reply_max*0.8 + reply_ge10*3       // 楼内战绩（主信号）
exposure  = root_like * 0.35                                      // 根评论能借出的曝光
slot      = 1 / (1 + 0.5*max(0, rcount+1-3))                       // 抢不到前 3 条就衰减
opportunity = (exposure + proof + 1) * freshness * slot
```

**代价**：每楼多 1 次 `/x/v2/reply/reply` 请求；`freshness` 用生命周期平均速度，"曾经很热但正在冷却"的视频会被低估。

**回滚**：`Tool\bili\hotthread.mjs` 文件头公式段 + `signals` 字段都在；`git checkout` 该文件即可回到 v1。

### D3 · 2026-10-19 22:49 · `ledger.mjs` 增加归因标签

**证据**：7 条评论、3 个赞却没有一个结构化标签，"什么样的评论能拿赞"无法回答。

**决策**

- `add` 增加可选 `--style short-punch|long-arg|question|info`、`--thread-size <根评论赞数>`；
- 新增 `label --rpid <id> [--style] [--thread-size] [--at]`：**只补标签，不取网络、不动赞数历史**；
- `report` 每条输出 `style / thread_size / age_hours / like_per_hour`。

回填 7 条后归因（n=7）：`short-punch 3 条 4 赞` vs `long-arg 4 条 0 赞`。

**代价**：标签由人或 LLM 判定，**只能用于规划，不能进入判定**。

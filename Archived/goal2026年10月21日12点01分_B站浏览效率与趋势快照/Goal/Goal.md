## 量化指标

### M1 交付完整度
1. 有效快照数 S >= 4（丢失留痕）
2. 每份时点偏差 ≤ 10 分钟
3. 缺采 = 0（单时段自动重试1次，仍失败记缺采）

### M2 快照规格（每份必须全含）
1. 全站排行 Top50、分区热度 Top10、搜索热词 Top10、上升榜 Top20
2. 原始条目 N ≥ 100
3. 字段固定：bvid / title / owner / view / like / coin / fav / reply / pubdate / rank / zone
4. 原始响应保留于 History/ 可复算，不删除

### M3 浏览效率（"最佳实践"的量化口径）
1. E1 压缩率 = raw_bytes / digest_bytes ≥ 8x
2. E2 单快照 LLM 可见字节 ≤ 4 KB
3. E3 单快照 LLM 调用 ≤ 2 calls
4. E4 全程 LLM 调用总数 ≤ 700 calls（硬上限 850）
5. E5 信息保留：趋势结论抽检可复原 ≥ 9/10
6. E6 完成1次对照实验：同一时点「raw 直读」vs「脚本压缩」两条路径，记录 token 与结论一致率

### M4 趋势质量
1. 相邻快照 bvid 重合度中位数 ≥ 70%（共5组）
2. 每份快照给出 ≥ 3 条可证伪趋势判定
3. 收尾产出：6快照趋势总表 + 1份《LLM浏览效率最佳实践》

### M5 可信度
1. 100% 判定数据由 Tool/ 下脚本产出，每文件带 params + sha256 + 脚本版本
2. audit 失败项 = 0
3. 额度对账由 Tool/bili/budget.mjs 读 cost-meter 账目，非人工声称
   
### M6 迭代频率（v2 新增）
1. L0 流式样本 ≥ 240 条/48h（light 10min + full 30min），缺失率 ≤ 5%
2. L2 LLM 批读轮次 ≥ 20 轮，每轮必须覆盖自上次以来的全部新样本，不得跳读
3. L1 事件（History/events.ndjson）每个须在 ≤ 2 小时内被至少一轮 L2 读到
4. 单样本采集消耗 LLM 调用 = 0（脚本自治）
5. L0 高频样本只支撑 delta 与曲线，不计入 M1 的官方快照数；官方仍为 6 份

### M7 风控证据
1. History/probe_risk.json 存在，且给出安全采样间隔结论
2. 采样期间所有非 0 风控码完整记录，出现即触发 L1 事件

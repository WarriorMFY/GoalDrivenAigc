# Desc-to-Spec 模糊需求转译器

## 任务目标
把感性、模糊的业务目标（Desc）翻译成可量化、可验证的规格指标（Spec），即把“语文题”翻译成“数学题”。触发条件：描述含主观形容词（好、活跃、有潜力）或无法直接写为代码/SQL/步骤的目标。

## 操作步骤

1. 实体抽取——识别核心名词，分环境限制、主体属性、范围定义三类节点。
2. 状态翻译——把形容词/模糊动词译为可测维度（“有潜力”→增长率、留存率、互动频次）。
3. 量化阈值——为每节点设具体数字/公式（“一段时间”→“近30天”）。
4. 盘问用户（Grill）——先问用户选填空还是选择，再按所选模式，对各不确定点（口径、阈值、数据可取性）强制一问一答：一次一个问题，回答定稿后再问下一个。凡不确定均以用户回答定稿，不自行假设。
   - 填空模式（Open）：自由手写，如“请填写‘活跃’的具体口径”。
   - 选择模式（Choice）：给出 A/B/C 候选并标注推荐，如“把‘有潜力’理解为？A. 近30天粉丝增长率>20%（推荐）　B. 互动率>5%　C. 自定义”，用户回复字母即选。

## 输出格式

```markdown
### 目标描述 (Desc)
[原始模糊需求]

### 量化指标 (Spec)
1. [环境/平台层]：阈值
2. [主体/对象层]：阈值
3. [状态/动作层]：衡量维度与公式
4. [范围/群体层]：规模与活跃度定义

### 下一步建议
- [ ] 明确各指标的数据源
- [ ] 建模将多指标综合为单一评价指数
```

## 使用示例
- 示例1：“找出有潜力的账号”→产出“近30天粉丝增长率>20%、月留存率>50%”。
- 示例2：“评估一个项目是否健康”→译为曝光量、转化率、现金流并设阈值。
- 要点：口径先问模式再推进；阈值定稿来自用户回答；选择模式每项附推荐。

## 注意事项
- Spec 严禁使用“表现好”“活跃”“适合”等定性词，一律用 >、<、= 加数字。
- 首版允许空缺，先搭骨架暴露盲区，再快速迭代。
